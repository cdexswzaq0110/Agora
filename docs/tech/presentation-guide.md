# 講解指南

給你在面試、社群分享或向同事介紹 Agora 時使用。每一段都可以單獨拿出來講。

---

## 30 秒版（電梯簡報）

> Agora 是一個讓 Claude 和 GPT **先討論、再動手**的平台。兩個模型會先各自提案、互相挑錯，整合成一份有驗收標準的方案；我核准之後，它們才在隔離的 git 分支上實作、跑測試，再依驗收標準互相審查。它只用我自己的 Claude 和 ChatGPT 訂閱，透過官方 CLI 驅動，**從架構上就不可能用到付費 API key**。另外，它每天早上會把 Hacker News、GitHub Trending 等社群的熱門話題整理成中文摘要給我。

## 3 分鐘版（講三個重點）

1. **問題**：單一模型的盲點很難靠它自己發現；兩個模型各說各的，又需要人來回複製貼上。而且模型一動手就在花錢、改檔案，我希望在那之前先確認方向。
2. **做法：方案工作坊**
   - 第一輪**獨立提案**：兩個模型同時寫，看到的上下文完全相同，避免後寫的被前面帶著走。
   - **互評**時要打分數（正確性、簡潔度、風險、成本、可測試性）。
   - **整合**成「可以直接交給工程師」的方案，必須包含編號的驗收標準。可以再加一輪**紅隊**專門找漏洞。
   - **核准關卡**：我可以改方案、要求修訂，或者只保留方案。
   - 實作在 **git worktree** 裡進行，我的工作目錄不會被碰到。審查者**依驗收標準逐條打勾**，最後我看 diff 決定要不要套用。
3. **可信度：證據等級**。每個結論都有「已確認／推論／候選／未知／未驗證」五級之一，而且等級的上限是**程式決定的**，不是模型自評：沒有跑過驗證指令並通過，就不可能是「已確認」。

## 10 分鐘版（加上架構與取捨）

依序講：

1. **架構圖**（[01](01-overview.md)）：Rust 引擎、內嵌的 axum 伺服器、Tauri 外殼；網頁、桌面、手機共用同一套介面。
   - 取捨：手機一定要走 HTTP，所以乾脆讓桌面也走 HTTP，只維護一套前端（ADR 0002）。
2. **CLI 驅動**（[03](03-providers-and-billing-guard.md)）：用 `claude -p --output-format stream-json` 和 `codex exec --json` 驅動，提示詞從 stdin 送入，逐行解析串流事件。
   - 三層計費防護：清除環境變數、檢查 Claude 的 `apiKeySource`、確認 Codex 的帳號類型；無法確認時不執行（fail closed）。
3. **成本控制**：每個議題都有發言上限、修訂上限，以及在呼叫前就攔下的額度保護和自動改派。
   - 實測數字：實作一次大約占 Plus 方案 5 小時額度的 8%，所以核准關卡放在實作之前。
4. **記憶**（[07](07-memory-and-context.md)）：
   - 對話太長時做擷取式記憶壓縮：不花額度、結果確定，而且一定留下標記。
   - 專案記憶太長時，用 TF-IDF 加中文雙字詞，檢索和議題最相關的條目。
5. **每日情報**（[05](05-daily-digest.md)）：只抓列表頁；排序考慮來源權重、你關注的主題、跨社群熱度；只花一次模型呼叫，而且要求每句話都附來源編號。
6. **踩過的坑**（[lessons](../lessons/INDEX.md)），挑兩則講：
   - Claude CLI 登入失敗時，回傳的 `subtype` 竟然是 `success`，要看 `is_error` 才知道失敗。
   - 由 Agora 驅動的 Codex 載入了我個人的電腦操控 MCP 工具。所以加了「隔離 CLI 個人設定」，而且預設開啟。

## 示範腳本（約 5 分鐘，示範模式不花額度）

```bash
cargo run -p agora-server -- --demo
```

1. 首頁：指出頂部的 HP 條（剩餘額度），以及「範本」區（說明是從自己的 skill 庫整理出來的）。
2. 選「新功能：先討論方案再實作」範本，參與者選兩個模擬模型，議題寫「`[mock:write]` 新增匯出功能」，驗證指令填 `echo ok`，按開始。
3. 議題頁：進度條依序走過提案、互評、整合、紅隊；兩份提案並排顯示；停在「等你核准」。
4. 切到「編輯」改一行字，核准；看它在 worktree 實作 → 驗證 → 審查表 → 結論「已確認」。
5. 工作區：點「查看 diff」，再點「套用到專案」，說明「不 commit，由我自己 commit」。
6. 情報頁：展示摘要裡的 `[n]` 引用連結，點一個卡片上的「延伸討論」，說明它會直接變成一場辯論的議題。
7. 用量頁：額度走勢和每日 tokens 圖表。

## 常見問答

| 問題 | 回答重點 |
|---|---|
| 為什麼不用 API？ | 使用者的明確要求，也是成本可預測的做法。訂閱額度看得到上限；API 用多少算多少。而且 CLI 本身就是能讀檔、改檔、跑指令的 agent，不必自己重寫工具層。 |
| 兩個模型不會互相附和嗎？ | 第一輪強制獨立；互評要打分數，並要求「如果自己的提案比較差就直說」；可以開盲審；辯論用交叉裁判，兩個裁判意見不同時直接標示分歧。 |
| 模型自己說「已確認」怎麼辦？ | 程式會把等級壓在「推論」以下，除非驗證指令真的跑過並通過。 |
| 會不會把我的專案改壞？ | 寫入在 git worktree，套用前看 diff；套用後也只是尚未 commit 的修改。 |
| 手機安全嗎？ | 預設只監聽本機；手機要用一次性的配對碼換 HttpOnly cookie；手機不能改 CLI 路徑或配對設定；有防 CSRF 和 DNS rebinding。 |
| 為什麼選 Rust 和 Tauri？ | 打包成單一 exe、不需要另外裝執行環境；Tauri 比 Electron 小很多。後端和桌面外殼共用同一個程序。 |
| 怎麼證明它真的能用？ | 112 個自動化測試，加上實機紀錄（見開發日誌）：Codex 在 worktree 寫出可以通過驗證的程式碼、真實抓取 5 個來源並整理成摘要。 |
| 這套「先討論再實作」自己有用過嗎？ | v0.3 的介面改版就是這樣做的：Claude 與 GPT 各自提案、互評打分、整合，GPT 再紅隊審視，然後才寫程式。紅隊找出 9 個高嚴重度問題（例如重繪會吃掉焦點、語音按鈕的事件越綁越多），全部有逐條處理紀錄。見 `docs/design/2026-11-16-ui-v0.3/`。 |
| 可以直接把實作交給 GPT 嗎？ | v0.4 的手機 QR 連線就是這樣做的：GPT 在獨立的 git worktree 裡寫程式、不能 commit，Claude 審查 diff 後才合併。審查抓到 GPT 的版本在繁體中文 Windows 上完全不能用（PowerShell 輸出不是 UTF‑8），修正後才進主線。第一次執行還意外發現 Agora 自己的 bug：隔離 CLI 設定會讓 Codex 寫不進檔案。 |
| 有什麼還沒做好？ | Reddit 的匿名存取時好時壞；第三家模型被擋住（沒有安裝 CLI，也無法確認計費方式）；Claude 的實機執行要等重新登入。這些都寫在 devlog 裡，沒有藏起來。 |

## 可以強調的工程習慣

- **每個坑都留下有證據的 lesson**，規則因此跟著改變（12 則）。
- **ADR 記下為什麼**，而不只是做了什麼（4 份）。
- **證據等級**用在文件、結論和這份講稿裡，用的是同一套詞彙。
- **成本是設計的一部分**：有上限、可見、在花之前先問。
