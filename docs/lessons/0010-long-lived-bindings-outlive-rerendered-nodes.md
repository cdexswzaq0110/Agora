# 0010 — 長期存在的綁定，會比被重繪的節點活得更久

- **Date**: 2026-11-16
- **Grade**: 已確認（兩個實例，都在瀏覽器重現與驗證修正）

## 發生了什麼

前端用 `innerHTML` 重繪，但有些東西掛在不會被重繪的物件上：

1. **事件委派越綁越多**：`bindVoice(view())` 每次進首頁或議題頁都在同一個 `#view`（跨頁存在）加一個 click listener；議題頁重繪核准面板時又綁一次。點一下語音按鈕，第一個 handler 開始收音，下一個看到「正在收音」就把它停掉。這是 v0.2 就有的 bug，由 GPT 紅隊審視指出。
2. **觀察器盯著已被替換的節點**：精簡標題列用 IntersectionObserver 觀察頁首的 `h1`。頁首一重繪，`h1` 換成新節點，觀察器還在看舊的（已脫離 DOM，永遠「不在畫面內」），結果在頁面最上方標題列也一直顯示。

## 證據

- 實例 2：重繪前 `#sSticky.hidden === true`；重繪後在頁頂仍是 `false`。修正後，捲動中重繪、回到頁頂再重繪，四種情況都正確（1320×860，`afterRepaintTop: true`）。
- 實例 1：程式碼路徑可直接讀出（`home.js` 與 `session.js` 每次 render 都呼叫 `bindVoice(view())`）；語音辨識本身在這台電腦的面板裡無法實測，修正後的「每個 root 只綁一次」用 WeakSet 保證。

## 規則

- 綁在跨頁存在的節點（`#view`、`document`）上的委派，只能綁一次（WeakSet 或模組層級註冊）。
- 觀察器（Intersection／Resize／Mutation）觀察的若是會被重繪的節點，每次重繪後要檢查節點是否換了，換了就重新觀察。
- 同類問題：頂欄高度在載入後會變（額度表晚到、徽章出現），只在 `resize` 時量測會過期，改用 ResizeObserver。
