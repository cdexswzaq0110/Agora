# v0.4 · Claude 對 GPT 提案的互評

> 第二輪。寫完之前沒有看到 GPT 對 Claude 提案的互評。

## GPT 比我好的地方（採用）

1. **推理強度要由後端驗證。** 我只說「介面只列可選的值」；GPT 要求 `/api/providers` 回傳 `supported_efforts` 與 `default_effort`，後端遇到不支援的值回 400、不靜默降級。這才擋得住 MCP、排程、舊範本這些不經過介面的入口。切換模型時保留仍合法的值、否則回到「模型預設」，預設選項寫成「模型預設（low）」也比我的設計清楚。
2. **「升溫」的定義更嚴謹。** 只在同一來源、有可比較指標（score、comments、stars_today）時才算升溫；昨天缺檔、來源失敗、沒有指標時只能說「新出現／持續」。我的「高 30%」沒有限制來源，會拿不同單位比較。舊檔案在讀取時補算、不回寫歷史，也比我的做法乾淨。
3. **未讀要看 `generated_at`。** 同一天重新整理（例如早上第一次失敗、按「立即更新」重做）應該重新變成未讀；我的「已讀日期集合」漏了這個情況。
4. **留言要能降級。** 方案修訂後段落可能消失；保留 `quote`、標示「原段落已變更」、絕不掛到別的段落，這個原則我沒寫。
5. **記憶句的伺服器端清理**（去換行、限長、拒絕空值），以及「不自動寫入、一定要人確認」。
6. **情報頁的驗收用量測**：第一個重點的 top < 860、頁高上限。

## 我認為 GPT 有問題的地方

| # | 問題 | 建議 |
|---|---|---|
| 1 | `Ctrl/Cmd+K` 聚焦「全域導覽／命令列」：Agora 沒有命令列，要新做一個是範圍擴張；而且 Chrome、Edge、Firefox 都把 Ctrl+K 用在網址列搜尋，和它自己寫的「不攔截瀏覽器既有快捷鍵」矛盾 | 砍掉。只做 `?`、`g` 系列換頁、`/` 聚焦目前頁面的搜尋或篩選 |
| 2 | `g` 再按 `i/u/s`：少了回首頁，`i` 對應「情報」不直覺 | `g h`／`g d`（digest）／`g u`／`g s`，說明對話框列出來 |
| 3 | 沒提 WCAG 2.1.4（單鍵快捷鍵必須能關閉或只在聚焦時生效） | 設定頁加開關；`g` 序列與 `?` 都屬單鍵，必須可關 |
| 4 | `ReasoningEffort` 寫成封閉 enum（含 `ultra`）：Claude 沒有 `ultra`，luna 也沒有；CLI 新增值就要改程式 | 存成字串，**依能力清單驗證**：Codex 用 `model/list`（動態、快取），Claude 用 `--help` 解析出的清單。驗證邏輯一致，但不把值寫死在型別裡 |
| 5 | 「需 Claude CLI 2.1.252+」：這是這台電腦的版本，不是 `--effort` 出現的版本，沒有證據 | 改成能力偵測：健康檢查時解析一次 `claude --help`（免費），有 `--effort` 才開放 |
| 6 | 未讀只存一個 `last_opened_date`：使用者翻開前天的情報時，最新那份會被當成未讀還是已讀？語意不清 | 存 `date → 讀過時的 generated_at` 對照表；最新一份「沒讀過」或「讀過之後又重新產生」就是未讀 |
| 7 | 逐段留言以 heading／paragraph／list 為單位，每個都有「留言」按鈕：一份方案 30–60 個 tab 停留點 | 以 `h2`／`h3` 段落為單位（工作坊方案本來就是「目標、做法、步驟、檔案、風險、驗收標準」）；段內細節用引文（quote）表達 |
| 8 | 「頁高不超過 3,500px」：高度取決於模型寫的摘要長度 | 用固定的示範情報量測，並以「完整清單預設收合」為條件；不同內容不要求 |

## 兩份都漏掉的

- **推理強度的其他入口**：範本、排程、同題比較、MCP 的 `start_session` 都帶著 `participants`，要一併支援並驗證；情報整理也要能設定強度。
- **預算提示**：推理越高 token 越多，首頁的「最多 N 次模型呼叫」旁邊要說明。
- **沒有模型時的情報**：趨勢標記也要出現在不用模型的備援摘要（`fallback_markdown`），不能只靠提示詞。
- **桌面系統匣**的「今日技術情報」打開時也要算已讀（走同一個 API）。

- Claude：範圍完整、介面細節具體（含 WCAG 2.1.4、段落級留言），但推理強度缺後端驗證、升溫定義會跨單位比較、未讀漏掉重新產生。
- GPT：資料語意與降級更嚴謹、驗收更可量測；扣分在 Ctrl+K 與 enum 寫死、少數未經證實的版本假設。

## 建議的最終範圍與順序

全部 8 項都做，加上 P7：

4. U3 未讀（`date → generated_at`）
5. U4 三頁重整（情報頁使用 R3／U3 的資料）
6. U1 手機底部導覽
7. R5 段落級留言（`block_id`＋`quote` 降級）
8. R6 記憶建議（可編輯、伺服器清理）
9. U2 快捷鍵（不含 Ctrl+K；可關閉）
