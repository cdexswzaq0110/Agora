## 採用的做法

### A. 首頁工作台（兩者）

1. Hero 縮成「一行介紹＋CLI 狀態」。未就緒的 CLI 改成一行提示加「查看」連結，不再顯示大型橫幅。
2. **待你處理列**：在撰寫區之上**最多顯示 1 筆**最高優先的項目（等待核准優先，其次是進行中），並附上「還有 N 項」。這樣待辦再多，也不會把輸入框擠出第一個畫面。
3. **撰寫區**由上而下：
   1. 專案下拉選單和「從範本開始」下拉選單（原生 `<select>`，鍵盤可操作）。
   2. 協作方式的分段按鈕：工作坊、單人、協做、討論、辯論，用短標籤。手機上允許換成兩行。
   3. 議題輸入框與語音按鈕。
   4. **流程摘要列**，例如「提案 Claude、GPT → 總結 Claude → 實作 Claude → 審查 GPT · 紅隊 · 隔離實作」，最右邊是「調整 ▾」。
   5. 開始按鈕與呼叫次數預估。
4. 「調整」展開後是參與者細項、修訂次數、驗證指令、發言上限、各種開關，以及同題比較。原本的功能全部保留，只是預設收起來。
5. 撰寫區下面是議題紀錄（搜尋、卡片），使用一致的空狀態。

### B. 待核准徽章（兩者）

導覽列「議題」顯示等待核准的數量；頁面標題也會加上「(N)」。資料來自 `GET /api/sessions`（所有專案），收到 SSE 的 `status` 事件時同步更新，並透過隱藏的 `aria-live` 區域朗讀。

### C. 核准面板只用一層捲動（兩者）

- 移除方案預覽的 `max-height` 與 `overflow`。
- 寬度 ≥ 980px 時是兩欄：左邊是方案文件，右邊是 **sticky 決策欄**（驗證指令、核准、要求修訂與其輸入框、只保留方案）。
- 手機上是單欄，決策區放在方案下面，主要按鈕至少 44px 高。不使用跨整頁的 fixed 底部列。
- 預覽／編輯補齊 `role="tab"`、`aria-selected`、`aria-controls`、`role="tabpanel"`，並且可以用左右方向鍵切換。

### D. 議題頁先顯示成果（GPT），加上階段導覽（Claude）

1. 順序：標題區 → 進度條 →（等待核准時）核准面板 →（完成時）結論 → 工作區與 diff → 方案 → 討論過程。
2. 討論過程依「輪」收合成 `<details>`。摘要列是階段名稱，加上**每則發言一行**：角色、模型、第一句、耗時、tokens。
   - 進行中：只展開最新一輪。
   - 等待核准或已完成：全部收合。
   - 你手動展開或收合的狀態，在重新繪製後保留（以輪為單位記住）。
   - 提供「全部展開／全部收合」。
3. 側欄最上面是「階段」目錄，可以點擊跳轉並自動展開該輪；跳轉目標有 `scroll-margin-top`。
4. 在 DOM 裡，側欄放在討論過程之前；桌面用 grid 把它排到右邊，手機就自然排在前面。手機上的過程紀錄預設收合。
5. 頁首的次要操作（下載 Markdown、寫成 ADR、lesson 草稿、複製結論、以此為範本）收進「更多 ▾」；只有主要操作（停止，或存入專案記憶）一直顯示。

### E. 焦點與即時宣告（GPT）

- 換頁後把焦點移到 `h1`（`tabindex="-1"`、`preventScroll`）。**SSE 更新時不移動焦點**。
- 狀態與階段變化寫進隱藏的 `aria-live="polite"` 區域。
- 核准或送出修訂後，把焦點移到更新後的狀態列。

### F. 手機與觸控（GPT）

寬度 ≤ 760px 時，按鈕、分頁、分段按鈕的最小高度是 44px；不能有水平捲動。

### G. 一致的空狀態與「正在更新」（Claude）

只套用在首頁與議題頁。更新中不調低透明度，而是顯示一個明確的「正在更新…」標記。

## 驗收標準（以 GPT 的版本為主）

1. 在 1320×860、淺色主題下，專案、議題輸入框、流程摘要和開始按鈕**全部位於第一個畫面內**（底邊 ≤ 860px）。
2. 有等待核准的議題時，首頁頂部 360px 內看得到它的標題、狀態和「檢視並核准」；從首頁只要點一次就能進入核准面板。
3. SSE 收到 `awaiting_approval` 時，待辦列和徽章不必重新整理就會更新。
4. 核准面板沒有內層垂直捲動；在 1320×860 閱讀長方案時，決策欄一直看得到。
5. 7 則發言的工作坊在等待核准時，討論過程預設全部收合，但每則發言都還有一行摘要；完成的議題，結論和工作區排在討論過程之前。
6. 375px 寬度下沒有水平捲動，主要按鈕至少 44px 高，概況與階段目錄排在討論過程之前。
7. 預覽／編輯可以用鍵盤切換，`aria-selected` 正確。
8. 以下功能不能退化：深色主題、降低動態效果、五種模式、範本、語音輸入、Ctrl/Cmd+Enter、分岔、diff 套用。
9. `cargo test --workspace` 通過；所有改動過的 ES module 通過 `node --check` 和 import 檢查；在 1320×860 與 375px 截圖比對。

## 這一輪不做

手機底部全站導覽、全域快捷鍵、情報未讀點（要先定義已讀狀態存在哪裡）、重整情報／用量／設定頁、全站元件化、任何框架或建置步驟。

整體證據等級：推論（兩份提案與互評都根據量測與程式碼；效果要等實作後的量測驗證）。

## 修訂紀錄：GPT 紅隊審視之後（2026-11-16）

GPT 的紅隊審視全文在 [`06-gpt-redteam.md`](06-gpt-redteam.md)。它讀檔時 Claude 還在改 `session.js`，所以有幾條在它寫完之前就已經修好；下表每條都標了實際處理方式。

### 高嚴重度

| # | GPT 指出的問題 | 判斷 | 處理 |
|---|---|---|---|
| 1 | 焦點先落在「載入中…」的 h1，被替換後就丟了；有焦點就整塊不重繪，會讓狀態卡住；核准後立刻聚焦狀態列，那時新狀態還沒到 | 成立 | `swap()`：只有 markup 變了才重繪，並用 id 或 data 屬性把焦點還原到新節點。核准面板只在「仍在等待核准且焦點在裡面」時跳過重繪，草稿、修訂文字和驗證指令都存在 `S` 裡。核准或修訂後設 `S.pendingFocus`，等狀態真的變了才聚焦狀態列 |
| 2 | 同一個「等待核准」會被宣告三次；階段變化沒有宣告 | 成立 | `announce(text, key)`：以 `session_id:status`（階段用 `session_id:phase:名稱:發言數`）去重 15 秒；拿掉 `refreshAttention` 的數量宣告；議題頁會宣告階段變化 |
| 3 | 「還有 N 項」算的是所有專案，連結卻只捲到目前專案的紀錄 | 成立 | 改成就地展開的全專案清單，每一筆都寫出專案名稱 |
| 4 | SSE 掉訊息或重連後，徽章可能一直是舊的；並行請求可能被較舊的回應蓋掉 | 成立 | 收到 `hello`（每次連線都會送）、`lagged`，以及分頁回到前景時，都會重新同步；`refreshAttention` 和 `loadSessions` 都只接受最新一次請求的回應 |
| 5 | 預覽沒有內層捲動了，但編輯用的 textarea 還有 | 成立 | textarea 隨內容長高（`overflow:hidden`）。驗收第 4 條改寫，見下方 |
| 6 | `<ul>` 放在 `<summary>` 裡不合法，也會讓按鈕的可及名稱包含所有摘要；摘要沒有模型名稱；「第一句」其實是第一行 | 成立 | 每一輪改成 `<h3><button aria-expanded aria-controls>` 的原生揭露模式，摘要清單放在按鈕外面；摘要加上模型名稱，用 。！？ 斷出第一句，失敗或撰寫中各有固定文字。「全部展開」改名為「展開所有輪次」，長發言自己的「展開全文」保留 |
| 7 | 語音輸入的 listener 會越綁越多；Ctrl/Cmd+Enter 可能重複開始 | 成立（這是 v0.2 就有的 bug） | `bindVoice` 用 WeakSet 保證每個 root 只綁一次，也拿掉核准面板的重複綁定；`startSession` 加上 `starting` 鎖，並忽略輸入法組字中的 Enter |
| 8 | 自動核准時摘要仍寫「你核准」；同題比較時摘要描述錯誤 | 成立（另外發現：只產出方案時一樣會自動核准） | 摘要改成照伺服器實際行為產生：`Engine::start_experiment` 讓所有模式都唯讀，工作坊只產出方案並自動核准；`approval_loop` 只要 `auto_approve` 就自動核准 |
| 9 | 驗收標準無法重現；`node --check` 不等於 import 檢查 | 成立 | 固定測試條件並改寫驗收標準，見下方。另外證實 `node --check x.js` 在 Node 24 對 ES module 裡的語法錯誤也會回傳 0，所以改成複製成 `.mjs` 再檢查 |

### 中、低嚴重度

| 問題 | 處理 |
|---|---|
| 「沒有水平捲動」定義太廣 | 改成 `scrollWidth === clientWidth`；diff、`pre`、表格可以各自捲動 |
| 同狀態的排序沒有定義 | 等待核准：等最久的排前面；進行中：最近更新的排前面；時間相同時依 id 排 |
| 「更多」用了 menu role，卻沒有 menu 的鍵盤行為 | 拿掉 role，用原生 `<details>`；Esc 關閉並把焦點還給按鈕；點外面或點項目也會關閉 |
| 降低動態效果時，JS 仍然平滑捲動 | `motion()` 會讀 `prefers-reduced-motion` |
| `--topbar-h` 從來沒有被設定 | 用 ResizeObserver 量測（實測：額度表載入後頂欄從 46px 變成 53px，手機上是 90px），而不是只在 resize 時量 |
| 手機上「更多」可能超出畫面；沒有處理安全區 | 手機上改成貼底的面板；頂欄、頁尾和插話列加上 `env(safe-area-inset-*)` |
| 首頁議題紀錄的非同步競態 | 每次請求記下 project、query、序號，三者都一致才畫上去 |
| 徽章的對比 | 白字配 `#c8742e` 實測只有 3.50:1，改成 `#a3501f`（5.64:1）；超過 99 顯示 99+ |
| 手機上模式按鈕換行後，邊框不連續 | 改成三欄 grid，每顆按鈕都有完整邊框 |
| 相對時間不會更新 | 待辦列每分鐘重畫一次 |
| 「正在更新」的套用範圍不清楚 | 議題紀錄和 diff 載入會顯示；其他讀取只要一次請求就完成，不另外加標記 |

### Claude 自己驗證時另外發現的 bug（不在紅隊清單裡）

- 改過方案之後就切不回「預覽」，因為是用「有沒有草稿」而不是「選了哪個分頁」判斷要顯示什麼。改成用 `S.planTab`，並加上 Home/End 鍵。
- 頂部的精簡標題列在頁首重繪後永遠顯示：IntersectionObserver 還在觀察已被替換掉的舊 h1。改成 h1 換了就重新觀察；標題列也改成 `position: fixed`，出現時不會讓內容跳動。
- 手機上「前往核准」只會捲到方案開頭，但決策欄排在整份方案下面。改成直接捲到決策欄；另外加上只在窄螢幕顯示的「跳到核准決定 ↓」。這個連結必須攔截點擊，否則 hash 會被 router 當成換頁。

### 修訂後的驗收標準

**測試條件**：示範伺服器（`agora-server --demo`，使用 scratch 資料夾）；內建瀏覽器（Chromium）；先清空 localStorage；縮放 100%；淺色主題，另外用深色主題再看一次。量測一律用 `getBoundingClientRect()`，不靠肉眼。

1. 1320×860：`#projSel`、`#prompt`、`#flowSummary`、`#startBtn` 的 `bottom` 都 ≤ 860。
2. 待辦列在頁面頂部 360px 內，而且列出所有專案的待辦。
3. 收到 `awaiting_approval`、`hello`、`lagged` 時，徽章、標題和待辦列不必重新整理就會更新。
4. 核准面板（預覽與編輯）都只有頁面本身一層捲動；1320×860、修訂框收合時，捲動長方案的過程中，「核准」按鈕一直在畫面內。
5. 同第 5 條，另外要求：摘要包含模型名稱，按鈕的可及名稱只有「階段名稱，N 則」。
6. 375px：`scrollWidth === clientWidth`；`#view` 裡的按鈕、summary、input、select 和頂欄導覽，高度都 ≥ 44px。
7. 預覽／編輯可以用 ←→ 和 Home/End 切換，`aria-selected` 和 `tabindex` 都正確；修改過的內容在兩個分頁之間切換不會遺失。
8. 不能退化的功能同原第 8 條；流程摘要另外用 10 種組合的表格逐一核對。
9. `cargo test --workspace` 通過；每個 module 複製成 `.mjs` 後通過 `node --check`；在瀏覽器載入後 console 沒有 error，而且 13 個 module 都回 200。
