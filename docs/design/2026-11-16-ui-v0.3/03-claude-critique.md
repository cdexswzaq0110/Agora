# UI v0.3 · Claude 的互評

> 寫在看到 GPT 的互評之前。

## 對 GPT 提案的評論

| GPT 的項目 | 看法 |
|---|---|
| 1 頁首「待你處理」工作列 | **同意**，和我的 P2 相同。補充：只放在首頁不夠，使用者可能正在情報頁或設定頁，所以導覽列的數量徽章應該是**必做**，不是「可以加」。 |
| 2 撰寫區優先 | **同意**。保留一點：把「其他四種模式」全部收進 `<details>` 會讓討論與辯論很難被發現。建議模式改成**一排精簡的分段按鈕**，一直顯示；收起來的是參與者細項、範本說明和進階設定。 |
| 3 方案文件加決策欄 | **同意，而且比我的方案好**。我原本提的是黏在面板底部的操作列；GPT 的寬螢幕右側決策欄能同時放驗證指令和三個按鈕，資訊更完整。手機版改成單欄，操作列黏在底部。 |
| 4 逐字稿依階段收合 | **同意方向，但有風險**。這個產品的價值之一，就是看得到兩個模型怎麼爭論出方案。完成後如果把整段討論都藏進「查看討論過程」，使用者會失去「為什麼」。建議收合後仍保留**每則發言一行的摘要**（角色、模型、第一句結論、耗時與 tokens），點一下展開全文。進行中則只展開目前階段。 |
| 5 降低模式與範本的選擇成本 | 同意。範本改成只顯示名稱的快速選單即可。 |
| 6 依裝置安排優先順序 | **同意，而且比我的「底部分頁列」更根本**。概況放在逐字稿之前、次要操作收進「更多」、按鈕至少 44px，這些都應該先做。底部分頁列可以之後再做。 |
| 7 鍵盤與 ARIA | **同意**，這是我漏掉的。注意：「換頁後把焦點移到標題」只能在換頁時做，SSE 更新時不能搶走焦點，否則會打斷正在打插話的人。 |
| 不做的事 | 全部同意，尤其是「不要用 modal」和「不要預設自動核准」。 |

## 對我自己提案的檢討

- **寬螢幕右欄**：76rem 的內容寬度切成兩欄後，撰寫區會變窄；GPT 的單欄加上頂部待辦列更簡單，效果也差不多。**撤回**，改成待辦列加上撰寫區下方的紀錄。
- **議題頁目錄**：依階段收合之後，目錄的價值降低，但仍有用。可以把每個階段的收合標題本身當成目錄，用 sticky 的階段導覽就能跳轉，不必另外做一份目錄。
- **快捷鍵**：便宜，但優先順序低；輸入框有焦點時必須停用。
- **漏掉的**：ARIA 語意、次要操作收進「更多」、完成後先顯示結論與 diff 再顯示逐字稿。
