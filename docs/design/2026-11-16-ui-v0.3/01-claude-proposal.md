# UI v0.3 · Claude 的獨立提案

> 寫在看到 GPT 提案之前（第一輪獨立提案）。

## 實測到的問題（1320×860，淺色）

| # | 問題 | 量測／觀察 |
|---|---|---|
| P1 | 首頁的主要任務（寫議題）埋在第三個畫面 | 首頁高 3,218px；「議題」輸入框在 y≈2,301；大標語就占滿第一個畫面 |
| P2 | 「需要你處理」的事情看不到 | 等待核准的議題只出現在最底部的紀錄卡片（y≈2,785） |
| P3 | 設定流程太長、太散 | 專案、範本（9 張大卡）、模式（5 張）、參與者（5 格）、議題、選項、比較：一路往下 6 個區塊 |
| P4 | 議題頁很長，難以跳轉 | 7 則發言的工作坊頁面高 5,013px，沒有目錄 |
| P5 | 核准面板裡又有捲軸 | 方案預覽 `max-height: 34rem` 會在頁面裡再捲一次；核准按鈕在預覽框下面，不一定看得到 |
| P6 | 導覽列沒有狀態提示 | 有議題在等你核准時，「議題」分頁沒有任何標記 |
| P7 | 手機版導覽在頂部第二行，要用拇指點很遠 | 375px 時，nav 位在 header 的第二行 |

## 提案（依優先順序）

1. **首頁改成「工作台」**：
   - 大標語縮成一行介紹；第一個畫面就是「寫議題」。
   - 寬螢幕分成兩欄：左邊是撰寫區，右邊是「需要你處理」（等待核准、進行中）、最近的議題、今日情報的前三則。
2. **撰寫區精簡**：
   - 議題輸入框放在最上面。
   - 模式改成一排分段按鈕，說明文字收在下方一行。
   - 參與者用一行摘要呈現（例如「提案 Claude、GPT → 總結 Claude → 實作 Claude → 審查 GPT」），按「調整」才展開細項。
   - 範本改成「從範本開始」的橫向卷軸或下拉清單。
   - 進階選項收成一列「進階設定」。
   - 專案改成撰寫區標題上的選單。
3. **核准面板**：方案完整展開，不再有內層捲軸；操作列（核准、要求修訂、只保留方案）黏在面板底部，捲動時一直看得到。
4. **議題頁目錄**：右側欄加上各輪的目錄（提案、互評、整合……），點了直接跳過去；目前所在的輪次會標示出來。議題標題列在捲動時黏在頂部，精簡顯示狀態和目前階段。
5. **導覽列徽章**：「議題」分頁顯示等待核准的數量；「情報」分頁在今天的情報整理好、還沒讀時顯示一個點。
6. **手機版**：導覽改成底部分頁列；撰寫區的參與者摘要只有一行。
7. **鍵盤操作**：`N` 新議題、`/` 搜尋、`G` 加 `D` 跳到情報、`?` 顯示快捷鍵說明。換頁時把焦點移到頁面標題（無障礙）。
8. **一致的空狀態與載入狀態**：情報、紀錄、圖表都使用同一種空狀態樣式；載入中時保留舊的畫面並調低透明度，不讓版面跳動。

## 不做

- 不加任何前端框架或建置步驟（CSP、零相依性是刻意的設計）。
- 不改設計語言（github.io 的暖灰、細線網格、直角按鈕）。
