## 研究（Claude）

網路研究摘要在 [00-brief](../design/2026-11-17-v0.6/00-brief.md)。影響設計最大的三點：

- **Agent Skills 已是開放標準**（`SKILL.md`，Claude Code 與 Codex 都讀）：兩個 harness 可以共用一份 skill 來源。
- **`claude -p` 在設定重時 skill 可能完全不自動觸發**（社群 issue）：Agora 必須自己確定性地注入，而不是賭模型載入。
- 2026 年 harness engineering 的共識：入口檔短、生成與評估分開、兩階段審查（先規格、再品質）、外部驗證優於自評、每次換模型重新評估規則（＝SE 原有的消融紀律）。

## 坑

| 問題 | 對應 |
|---|---|
| 指紋用 `git diff HEAD` 的輸出：列出變更時 `git add -A`，同樣內容暫存前後指紋不同，第一次就通過的審查會被誤判為「驗證後又有變動」 | 瀏覽器驗收時在審查紀錄看到；指紋改成「與 HEAD 不同的路徑＋目前內容」，測試加上「驗證時＝交給審查者時」 |
| `extended/` 保留了同名的舊 skill，核心 skill 被停用時會退回注入舊版 | 篡改測試抓到；注入只用核心 |
| Bash heredoc 把反斜線減半 | [lessons/0015](../lessons/0015-bash-heredoc-halves-backslashes.md) |
| SE 的 Python hooks 在繁中 Windows 輸出 cp950 | SE 的 lesson L0006 |
| Codex 沙盒不准寫 `.agents/`、`.codex/` | SE-Codex 的安裝與設定由 Claude 完成 |
| 專案頁在手機上被很長的 worktree 路徑撐寬（v0.4 起就有；之前的示範程式庫不是 git，沒有工作區區塊） | `.workspace` 允許任意斷行 |
