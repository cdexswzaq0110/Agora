## 怎麼讀

- 想快速了解專案：先看 [README](../../README.md)，再看 [技術文件索引](../tech/README.md)。
- 想知道某個設計**為什麼**這樣做：看 [ADR](../adr/)。
- 想知道踩過哪些坑：看 [lessons](../lessons/INDEX.md)。
- 想準備口頭介紹：看 [講解指南](../tech/presentation-guide.md)。

## 寫新日誌的格式

每一筆日誌包含：

1. **起點**：使用者要什麼（盡量引用原話）。
2. **決策**：做了哪些選擇，理由是什麼；重大決策另開 ADR。
3. **實作**：改了哪些模組（連結到程式碼或技術文件）。
4. **證據**：測試數字、實機執行的輸出、截圖觀察；沒跑過的標「未驗證」。
5. **坑**：遇到的問題，對應的 lesson。
6. **還沒做／被擋住**：明確寫出來，不要靜默略過。
