## 起點

使用者原話：

> 完整 agora 視覺前端介面，可參考 https://cdexswzaq0110.github.io/ 的動態效果，且完成 tailscale 的連線。最核心的部分請你優化界面，核心是以一位工程師的開發專案 agent 模式去修改。我需要以後工作能用這套專案：從我的構思發想幫我建立完整工作流，分析專案可行性分析、技術面分析，並且核心要擁有 PM、UX、SA、Architect、SD、DBA、Dev、QA、DevOps\SRE、LLM 工程師、NLP 工程師、AI 工程師、系統設計師、系統架構師、資料分析師、ML 工程師、MLOps 工程師、DL 工程師等等，你全都必須一定要扮演的角色，讓我作為一個團隊。

途中追加：

使用者要求一個可拖曳的桌寵助理，用他自己做的角色（不可另外創作），角色相關的工作全部交給 GPT，Claude 不經手；也可以分配任務給 Codex 加速。之後使用者決定**角色的一切都不上傳**：角色圖、桌寵程式、樣式與人設只留在本機（見文末「使用者回饋之後」）。

## 審查 GPT 的修改時抓到的問題

| 模組 | 問題 | 處理 |
|---|---|---|
| 桌寵 | 桌寵程式被壓成 39 行（最長一行 2,049 字元），無法審查 | 交回 GPT 重排（497 行，無超過 160 字元的行） |
| 桌寵 | CSS 用了原始專案的變數名（`--shadow-lg`、`--accent`、`--user`、`--bg`、`--surface-2`、`--faint`），Agora 沒有定義：陰影、焦點框、訊息底色全部失效 | 交回 GPT 改用 Agora 的變數 |
| 桌寵 | rustfmt 改了 `api.rs` 一大片既有程式碼的格式 | 交回 GPT 還原，只留新增的測試 |
| 桌寵 | 聊天沒有長度上限、history 的 role 由用戶端決定、使用者內容可以關閉資料標籤 | 交回 GPT：訊息 2,000 字、history 8 筆 × 1,000 字、role 白名單、標籤中和；錯誤碼 400／409／502／503 |
| 桌寵 | 選單放在 `role="status"` 的泡泡裡，會被螢幕閱讀器整串朗讀；「連續活動 50 分鐘」從不歸零 | 交回 GPT：獨立的 `role="menu"`（方向鍵、Esc、ContextMenu／Shift+F10）；閒置 5 分鐘歸零 |
| 動態效果 | 設定「開」在系統要求降低動態時沒有作用（三層限制） | Claude 修正，[lessons/0013](../lessons/0013-explicit-motion-on-was-clamped-at-three-layers.md)；桌寵端交回 GPT |
| 團隊介面 | 深度選項照 JSON 的字母順序排成「完整、快速、標準」 | 固定順序 |
| 團隊介面 | 工作流頁用裸的 rAF 合併事件，rAF 不觸發時之後的事件全被丟掉 | 改用共用的 `nextFrame()`，[lessons/0005](../lessons/0005-raf-does-not-fire-in-hidden-pages.md) 補記 |
