# 2026-11-16 · v0.3 介面改版（先和 GPT 討論，再實作）

## 起點

使用者原話：

> 開始繼續改進這個專案的介面，並且調用 GPT 討論實作。

所以這一輪用的正是 Agora 自己主張的流程：**兩個模型各自提案 → 互評 → 整合 → 紅隊 → 實作 → 驗證**。差別在於這次由 Claude Code 透過 Codex CLI（`codex exec`，ChatGPT 訂閱，不是 API key）手動跑這個流程，因為要改的正是 Agora 本身。

## 決策

| 決策 | 誰提的 | 理由 |
|---|---|---|
| 首頁改成工作台：待辦列＋輸入區＋一行流程摘要，細節收進「調整」 | 兩者 | 改版前實測（1320×860）：首頁高 3,218px，議題輸入框在 y≈2,301，等待核准的議題在 y≈2,785；首頁要能一眼看到「誰在等我」和「我要開始什麼」 |
| 待核准徽章（導覽列＋分頁標題） | 兩者 | 核准關卡是整個流程唯一需要人的地方 |
| 核准面板改成「方案文件＋sticky 決策欄」，只有一層捲動 | 兩者 | 原本方案在 34rem 的內層捲動，按鈕在面板外 |
| 議題頁先顯示結論與工作區，討論依輪收合，每則留一行摘要 | GPT | 完成後使用者要的是成果，不是逐字稿 |
| 側欄加上階段目錄 | Claude | 長議題需要導覽 |
| 焦點管理、`aria-live` 宣告、ARIA tabs、44px 觸控 | GPT | Claude 的提案沒有涵蓋無障礙 |
| 一律只用原生 HTML／CSS／JS，不加框架或建置步驟 | 兩者 | 維持 v0.1 起的限制 |
| 不做：手機底部導覽、全域快捷鍵、情報未讀點、重整其他頁 | 兩者 | 這一輪範圍控制在首頁與議題頁 |
